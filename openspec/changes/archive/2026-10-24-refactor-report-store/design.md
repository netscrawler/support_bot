# Design

## Context

Шесть вызовов `assemble` (`Load`, `LoadActive`, `GetByID`, `GetByName`, две ветки `LoadByEvent`) раскладывают поля разных sqlcgen-строк в девять позиционных аргументов. `Load` используется только `ctl export` через `service.ReportManager.Load`.

## Goals / Non-Goals

**Goals:** честный результат `Load`; один тип аргумента у `assemble`.

**Non-Goals:** менять sqlc-запросы; выносить новый тип наружу пакета `store`.

## Decisions

1. **Частичный результат (решение пользователя).** `Load` возвращает `(reports, errors.Join(... fmt.Errorf("report %s: %w", name, err)))`. Поведение описывается в doc-комментарии `service.ReportStore.Load`. Альтернатива «упасть целиком» отклонена: один сломанный отчёт не должен мешать выгрузить остальные.
2. **`ctl export`.** Сначала сохраняет все собранные отчёты, затем возвращает `fmt.Errorf("load reports from db: %w", err)`, если ошибка была. Раньше ошибка `Load` прерывала выгрузку, но при сбое сборки до неё не доходило.
3. **Один тип строки.** Все sqlc-строки, которые собирает `assemble`, имеют одинаковый набор полей, поэтому `assemble` принимает `sqlcgen.ListReportRowsRow`, а остальные вызовы передают `sqlcgen.ListReportRowsRow(row)` (преобразование структур Go). Отдельный `reportRow` с ручным копированием девяти полей не нужен; если колонки запроса разойдутся, преобразование перестанет компилироваться.
4. **Удаление `LoadActive`.** Метод и строка интерфейса `ReportLoader` удаляются, мок перегенерируется `go tool mockery`.

## Risks / Trade-offs

- [Скрипты, ожидающие нулевой код `ctl export` при сбое сборки] → это и есть исправляемое поведение; сообщение называет отчёт.
