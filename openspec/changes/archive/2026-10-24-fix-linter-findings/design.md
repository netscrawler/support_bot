# Design

## Context

См. `proposal.md`. Рабочее дерево уже содержит обширные незакоммиченные изменения; исправления должны сохранять их. Включено 17 анализаторов с 92 замечаниями. Go-сборка требует `CGO_ENABLED=1`.

## Goals / Non-Goals

**Goals:** устранить замечания исходной конфигурации линтера без массового отключения правил; сохранить существующие контракты; проверить полный проект.

**Non-Goals:** рефакторинг вне отмеченных мест, обновление зависимостей и изменение сгенерированного кода.

## Decisions

- Сначала исправлять явно безопасные замечания и повторы, затем проверки ошибок и предупреждения безопасности. Альтернатива — массовый `--fix`, но при текущем большом дифе он затруднит контроль.
- Для ошибок вывода HTTP не возвращать внутренние строки ошибок клиенту без экранирования. Альтернатива — подавить `gosec`, но это оставит реальную уязвимость.
- Для SQL-идентификаторов применять проверку/экранирование согласно контракту DuckDB. Значения остаются параметризованными. Альтернатива — подавить G201, но имена таблиц приходят из данных.
- В местах обработки rollback и close учитывать ошибку, когда от неё зависит результат операции; иначе явно документировать лучший возможный способ очистки.

## Risks / Trade-offs

- [Правки в большом незакоммиченном дереве] → проверять диф конкретных файлов и не сбрасывать существующие изменения.
- [Изменение обработки ошибок] → выполнить связанные тесты и полный проектный набор проверок.
- [Изменения Lua-песочницы] → отдельная проверка безопасности перед архивированием.
