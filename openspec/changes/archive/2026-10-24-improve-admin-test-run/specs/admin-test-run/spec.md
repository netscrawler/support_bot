# Spec Delta

## Purpose

Даёт администратору проверить отчёт до включения по расписанию: отчёт приходит только ему, вне зависимости от условия отправки, вместе с результатом условия и текстом ошибки, если что-то сломалось.

## ADDED Requirements

### Requirement: Доставка только запросившему админу
Пробный запуск из админ-меню («📤 Получить» в карточке отчёта) SHALL доставлять отчёт только в чат администратора, который нажал кнопку. Штатные получатели отчёта MUST NOT получать ничего. Отправленные сообщения MUST NOT сохраняться для удаления в конце дня.

#### Scenario: У отчёта три получателя
- **WHEN** админ запускает пробный запуск отчёта с тремя штатными получателями
- **THEN** отчёт приходит только админу, штатные получатели ничего не получают

### Requirement: Условие не блокирует пробный запуск
Пробный запуск SHALL генерировать и доставлять все форматы отчёта, даже если `evaluate` вернул false. После отчёта в тот же чат SHALL приходить строка с результатом условия; при false — с пометкой, что по расписанию отчёт не был бы отправлен.

#### Scenario: Условие ложно
- **WHEN** `evaluate` отчёта возвращает false, а админ запускает пробный запуск
- **THEN** админ получает отчёт и строку `🧪 evaluate = false` с пометкой, что по расписанию отчёт не был бы отправлен

#### Scenario: Условие истинно
- **WHEN** `evaluate` возвращает true
- **THEN** админ получает отчёт и строку `🧪 evaluate = true`

### Requirement: Ошибка видна админу
Если пробный запуск завершился ошибкой сбора, обработки, оценки условия или отправки, текст ошибки (до 500 символов) SHALL приходить в чат запросившего админа.

#### Scenario: Ошибка коллектора
- **WHEN** запрос отчёта падает с ошибкой
- **THEN** админ получает сообщение с текстом ошибки, отчёт не приходит

### Requirement: Пробный запуск в журнале
Пробный запуск SHALL записываться в журнал запусков с типом `test` и ID чата админа. Он MUST NOT вызывать уведомлений о сбое или восстановлении и MUST NOT учитываться при решении, слать ли такие уведомления.

#### Scenario: Пробный запуск упал
- **WHEN** пробный запуск завершился ошибкой
- **THEN** в журнале запись `test` со статусом `failed`, в служебный чат уведомление не приходит

### Requirement: ЛК пользователя без изменений
Получение отчёта пользователем в ЛК SHALL учитывать `evaluate` как раньше и MUST NOT присылать служебных строк про условие.

#### Scenario: Пользователь, условие ложно
- **WHEN** обычный пользователь запрашивает отчёт с ложным условием
- **THEN** отчёт не приходит, строки про evaluate нет, в журнале запись `lk` со статусом `skipped`
