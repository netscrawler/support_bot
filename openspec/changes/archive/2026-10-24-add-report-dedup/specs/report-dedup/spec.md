# Spec Delta

## Purpose

Не даёт отчёту, который часто срабатывает по cron, раз за разом отправлять одни и те же данные: повторная отправка без изменений подавляется, если для отчёта включена дедупликация.

## ADDED Requirements

### Requirement: Флаг дедупликации
У отчёта SHALL быть флаг `dedup` (по умолчанию false), который задаётся и экспортируется в JSON-описании отчёта. Если флаг выключен, поведение отчёта MUST NOT меняться.

#### Scenario: Старый JSON без флага
- **WHEN** через `ctl apply` загружается JSON отчёта без поля `dedup`
- **THEN** отчёт сохраняется с `dedup = false` и отправляется на каждом срабатывании, как раньше

#### Scenario: Экспорт
- **WHEN** выполняется `ctl export` для отчёта с `dedup = true`
- **THEN** в JSON отчёта есть `"dedup": true`

### Requirement: Подавление повтора по cron
Для отчёта с `dedup = true` запуск по cron, у которого условие выполнено, MUST NOT отправляться, если его данные совпадают с данными последнего успешного (`success`) запуска типа `cron` или `manual`. Такой запуск SHALL записываться в журнал со статусом `skipped` и причиной `duplicate` и MUST NOT вызывать уведомлений.

#### Scenario: Алерты не изменились
- **WHEN** отчёт с `dedup` отправился в 10:00, а в 10:05 cron собрал те же данные
- **THEN** в 10:05 ничего не отправлено, в журнале `skipped`/`duplicate`

#### Scenario: Данные изменились
- **WHEN** в 10:10 появился новый алерт
- **THEN** отчёт отправлен, в журнале `success`

#### Scenario: Первый запуск
- **WHEN** у отчёта с `dedup` ещё нет ни одного успешного запуска
- **THEN** отчёт отправляется

#### Scenario: Прошлая отправка не удалась
- **WHEN** последний запуск был `failed`, а предыдущий `success` — с теми же данными
- **THEN** отчёт не отправляется, потому что сравнение идёт с последним `success`

### Requirement: Что считается одинаковыми данными
Данные двух запусков SHALL считаться одинаковыми, если совпадают все листы датасета после обработки pipeline, кроме служебного листа `_meta`. Порядок ключей внутри строки MUST NOT влиять на результат, порядок строк — влияет.

#### Scenario: Меняется только время в `_meta`
- **WHEN** два запуска различаются только значением времени в листе `_meta`
- **THEN** данные считаются одинаковыми

### Requirement: Остальные типы запуска не подавляются
Запуски типов `manual`, `test` и `lk` SHALL отправляться независимо от совпадения данных. Успешный запуск `manual` SHALL становиться точкой сравнения для следующих запусков по cron.

#### Scenario: Ручной запуск тех же данных
- **WHEN** админ нажал «▶️ Запустить» для отчёта с `dedup`, данные не менялись
- **THEN** отчёт отправлен получателям
