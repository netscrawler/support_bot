# Design

## Context

Кириллица в Go-коде встречается в нескольких ролях: логи, тексты ошибок, сообщения Telegram, вывод CLI, `comment:`-теги конфига, Help метрик, данные шаблонов (названия месяцев), комментарии. Перечень строк для перевода получен AST-сканом: строковые литералы с кириллицей в аргументах вызовов `fmt.Errorf`, `errors.New` и `log.*Context`.

## Goals / Non-Goals

**Goals:**
- Все логи и тексты ошибок — на английском.

**Non-Goals** (договорённость с пользователем, 2026-10-24):
- Сообщения Telegram остаются на русском, в том числе вне `internal/tg_bot`: алерты runlog (`⚠️ Отчёт …`, `✅ Отчёт … снова работает`), строка `evaluate = false …` в `orchestrator.go`, `models.TgChat.String()`, `internal/tg_bot/service/tmpl.go`.
- Не трогаются: вывод и help CLI (`internal/cli/help.go`, описания флагов, таблица `ctl link list`, «ссылка отозвана»), `cmd/live-server`, `comment:`-теги конфигов, Help метрик Prometheus, названия месяцев в `internal/pkg/text`, комментарии в коде.
- Сгенерированный код (`internal/db/sqlcgen`) не правится.

## Decisions

- **Перевод дословный, структура сообщения сохраняется.** Префиксы (`grafana %s:`, `zabbix %q:`, `runlog:`, `query:`), глаголы форматирования и обёртка `%w` остаются на местах — так проще ревьюить и `errors.Is` не задевается. Стиль — как у соседних английских ошибок: строчные буквы, без точки в конце, без «error/failed to» в обёртках (`create date style: %w`).
- **Ошибки CLI `ctl link revoke` переводятся, остальной вывод CLI — нет.** Это ошибки, а не пользовательский вывод; смешение языков в CLI принято сознательно.
- **Тесты, проверяющие тексты (`ErrorContains`, `strings.Contains`), обновляются вместе с кодом в той же задаче.** Тестовые данные с кириллицей, которые проверяют обработку UTF-8 (`strings.Repeat("я"/"ы")`, `"Отчёт за %s"` в `parse_func_test.go`), и проверки русских Telegram-текстов (`"снова работает"`, `"Запусков пока нет."`) остаются.

## Risks / Trade-offs

- [Внешние алерты или дашборды фильтруют логи по русским сообщениям] → затронуты только 8 сообщений в `orchestrator` и `runlog`; перечислить их в описании коммита.
- [Пропущенная строка] → после правок повторить AST-скан; в выводе должны остаться только строки из Non-Goals.
