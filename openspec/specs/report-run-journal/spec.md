# report-run-journal Specification

## Purpose

Хранит историю запусков отчётов: когда отчёт запускался, кем, чем закончился и почему. По ней админ может ответить, дошёл ли отчёт до получателей, не открывая логи.

## Requirements

### Requirement: Запись каждого запуска
Каждый запуск отчёта, который проходит через оркестратор (по cron, ручной запуск из админки, запуск из ЛК), SHALL оставлять ровно одну запись в журнале после завершения. В записи: имя отчёта, тип запуска, статус, время начала и окончания. Генерация по публичной HTTP-ссылке в журнал не пишется.

#### Scenario: Успешный запуск по cron
- **WHEN** отчёт запущен по cron, условие выполнено и все получатели получили отчёт
- **THEN** в журнале появляется запись с типом `cron` и статусом `success`

#### Scenario: Генерация по публичной ссылке
- **WHEN** отчёт сгенерирован по запросу `GET /api/v1/public/report/{id}`
- **THEN** новой записи в журнале нет

### Requirement: Статусы запуска
Статус запуска MUST быть одним из: `success` — все получатели получили отчёт; `skipped` — условие `evaluate` ложно, отправки не было; `failed` — ошибка сбора, обработки, оценки условия, ни один формат не экспортировался или ни один получатель не получил отчёт; `partial` — часть получателей получила отчёт, часть нет. Для `failed` и `partial` в записи SHALL быть текст ошибки, для `skipped` — причина.

#### Scenario: Условие не выполнено
- **WHEN** `evaluate` отчёта вернул false
- **THEN** запись получает статус `skipped` с причиной `evaluate`

#### Scenario: Ошибка коллектора
- **WHEN** сбор данных завершился ошибкой
- **THEN** запись получает статус `failed` и текст ошибки, отправки получателям нет

#### Scenario: Один из двух получателей недоступен
- **WHEN** отчёт ушёл в Telegram-чат, а отправка на email упала
- **THEN** запись получает статус `partial` и текст ошибки email

#### Scenario: Все экспорты упали
- **WHEN** условие выполнено, у отчёта есть форматы экспорта, но ни один не сгенерировался
- **THEN** запись получает статус `failed` с ошибками экспорта, отправки получателям нет

#### Scenario: Нет ни одного получателя
- **WHEN** у отчёта с выполненным условием пустой список получателей
- **THEN** запись получает статус `failed`

### Requirement: Тип запуска и инициатор
Тип запуска MUST быть одним из: `cron` — по расписанию; `manual` — кнопка «▶️ Запустить» в админке (отправка штатным получателям); `lk` — генерация в чат того, кто запросил. Для `lk` в записи SHALL храниться ID этого чата.

#### Scenario: Запуск из ЛК
- **WHEN** пользователь запросил отчёт себе в чат
- **THEN** запись получает тип `lk` и ID чата пользователя

### Requirement: Срок хранения
Записи журнала старше срока хранения из конфига (по умолчанию 30 дней) SHALL удаляться автоматически не реже раза в сутки.

#### Scenario: Старая запись
- **WHEN** запись старше срока хранения, и после этого прошло больше суток работы бота
- **THEN** записи в журнале нет

### Requirement: Просмотр в админке
В карточке отчёта в админ-меню Telegram SHALL быть кнопка, которая показывает последние 10 запусков отчёта, начиная с новых: время, тип, статус, длительность и первые 200 символов ошибки или причины.

#### Scenario: Отчёт без запусков
- **WHEN** админ открывает запуски отчёта, который ещё ни разу не запускался
- **THEN** бот отвечает, что запусков нет, и показывает кнопку «Назад»
