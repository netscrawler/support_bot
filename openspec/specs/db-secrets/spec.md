# db-secrets Specification

## Purpose
Позволяет хранить токены и пароли коллекторов в БД зашифрованными и ссылаться на них из запросов отчётов по имени, не добавляя их в конфиг бота.

## Requirements

### Requirement: Шифрование секретов
Значение секрета MUST храниться в БД только в зашифрованном виде (AES-GCM, base64), ключом из `SECRETS_KEY` (32 байта в base64). Расшифровка с другим ключом или повреждённого значения MUST давать ошибку с именем секрета, а не мусорное значение.

#### Scenario: В таблице нет открытого значения
- **WHEN** секрет `billing_token` со значением `t0k` сохранён
- **THEN** в таблице `secrets` нет строки `t0k`, а коллектор получает `t0k`

#### Scenario: Сменился ключ
- **WHEN** секрет сохранён с одним ключом, а бот запущен с другим `SECRETS_KEY`
- **THEN** сбор запроса с этим секретом завершается ошибкой с именем секрета

### Requirement: Бот работает без ключа
Если `SECRETS_KEY` не задан, бот SHALL стартовать как обычно; ошибку SHALL давать только сбор запроса со ссылкой на секрет и команда `ctl secret set`. Ключ неверной длины MUST останавливать старт с понятной ошибкой.

#### Scenario: Нет ключа
- **WHEN** `SECRETS_KEY` не задан, в отчёте одна карточка с `secret` и одна без
- **THEN** вторая собирается, первая завершается ошибкой о незаданном `SECRETS_KEY`

#### Scenario: Ключ не той длины
- **WHEN** `SECRETS_KEY` — base64 от 16 байт
- **THEN** бот не стартует, ошибка называет `SECRETS_KEY` и ожидаемую длину

### Requirement: Управление секретами через ctl
`ctl secret set -name <имя> -host <хост>` SHALL читать значение из stdin и создавать или заменять секрет. `ctl secret list` SHALL выводить только имена. `ctl secret delete -name <имя>` SHALL удалять секрет и MUST отказывать, пока на него ссылается хотя бы один запрос. Расшифрованное значение MUST не выводиться ни одной командой.

#### Scenario: Создание из stdin
- **WHEN** `echo -n t0k | sbot ctl secret set -name billing_token -host billing.local`
- **THEN** секрет создан, в выводе нет `t0k`

#### Scenario: Удаление используемого
- **WHEN** запрос отчёта ссылается на `billing_token` и выполняется `ctl secret delete -name billing_token`
- **THEN** команда завершается ошибкой, секрет остаётся

### Requirement: Секрет привязан к хосту
Каждый секрет MUST храниться с хостом, на который его разрешено отправлять (`-host` в `ctl secret set`, обязателен). Хост MUST быть защищён шифрованием так, что подмена хоста в таблице без ключа делает секрет нерасшифровываемым. Коллектор MUST отправлять секрет только на этот хост (сравнение без учёта регистра; если в хосте секрета есть порт — с портом) и MUST давать ошибку с именем секрета и хостом запроса, не отправляя запрос, для любого другого хоста.

#### Scenario: Карточка на чужой хост
- **WHEN** секрет `billing_token` сохранён с `-host billing.local`, а карточка `card_uuid = https://evil.example/x` ссылается на него
- **THEN** сбор завершается ошибкой с `billing_token` и `evil.example`, запрос не отправляется

#### Scenario: Подмена хоста в БД
- **WHEN** в таблице `secrets` колонку `host` секрета вручную поменяли на `evil.example`
- **THEN** расшифровка секрета завершается ошибкой, значение не используется

#### Scenario: Свой хост
- **WHEN** секрет сохранён с `-host billing.local`, карточка `card_uuid = https://billing.local/api`
- **THEN** запрос уходит с этим секретом

### Requirement: Ссылка на секрет из запроса
Запрос отчёта SHALL ссылаться на секрет по имени в поле `secret` JSON DSL. `ctl apply` MUST отклонять отчёт со ссылкой на несуществующий секрет. `ctl export` SHALL выгружать имя секрета, но не его значение.

#### Scenario: Ссылка на несуществующий
- **WHEN** `ctl apply` отчёта с `"secret": "nope"`, секрета `nope` нет
- **THEN** применение завершается ошибкой с именем `nope`, отчёт не меняется

#### Scenario: Экспорт
- **WHEN** `ctl export` отчёта с `"secret": "billing_token"`
- **THEN** в выгрузке `"secret": "billing_token"` и нет значения секрета

### Requirement: Секреты из БД не попадают в ошибки
Текст ошибки сбора, который записывается в журнал запусков или отправляется администраторам, MUST не содержать значение секрета из БД, использованного этим запросом, — вместо него `***`.

#### Scenario: Значение в ошибке
- **WHEN** сбор запроса с секретом `t0k` упал с ошибкой, текст которой содержит `t0k`
- **THEN** в журнале запусков и в уведомлении вместо `t0k` стоит `***`
